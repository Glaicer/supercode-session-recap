# supercode.recap

TUI-плагин OpenCode: секция `Recap` в сайдбаре сессии. По клику сворачивает хвост
сессии в короткий Markdown — «над чем работаем / сделано / следующее» — и рисует его
прямо в сайдбаре, не добавляя ничего в тред.

Один файл `recap.tsx`, без сборки и без npm-зависимостей: рантайм транспилирует JSX сам.

## Как работает

1. Recap Digest — свёртка сессии из реактивного состояния TUI (`api.state.session.messages`),
   не по HTTP: одна строка на каждый tool-вызов (`[tool] имя аргумент -> ok|error: первая
   строка ошибки`; правки файлов дают путь и знак изменения `(+N -M)`, без содержимого
   диффа), `text`-части как есть с видимой обрезкой длинных, `reasoning` отбрасывается
   целиком. Бюджет в символах (`budget`, дефолт 12000): при переполнении материал
   отбрасывается **с головы окна** — хвост важнее; окно инкрементальное — после успешного
   Recap хранится `messageID`, который он покрыл, и следующий Digest берёт только сообщения
   после него, подавая предыдущий Recap отдельным блоком `PREVIOUS RECAP`. Факт усечения
   попадает в промпт явной строкой.
2. Recap Model — цепочка, первый валидный уровень побеждает: опция `model` из `tui.json` →
   `small_model` из конфига → модель последнего ассистентского сообщения сессии. Разбор
   строки — строго по первому `/` (`gonka-proxy/deepseek-ai/deepseek-v4-flash-0731`
   режется правильно). Каждый кандидат валидируется против списка провайдеров **до**
   вызова; невалидный/неизвестный даёт один error-тост на источник за процесс
   (`tui.json` / `small_model` / session) и цепочка идёт дальше. Если не разрезолвилось
   ничего — запрос уходит без поля `model`, сервер применит дефолтную.
3. Recap Session — одноразовая дочерняя сессия (`parentID`, `title: "recap"`); в ней один
   синхронный `session.prompt` со своим `system` и всеми тулами, выставленными в `false`
   (+ `"*": false` — пробник показал, что MCP-тулы через id-список не гасятся).
4. Markdown берётся из `parts` ответа; Recap Session удаляется в `finally` (неуспех удаления —
   тост). Ошибки вызова — тост, предыдущий Recap не трогается.

Чистая логика модели (`parseModelRef`, опции, валидация) и сборка Digest
(`buildRecapDigest`, `buildRecapRequest`) вынесены в файлы без TUI-импортов и покрыты
юнит-тестами: `node --test`.

## Опции

Второй элемент кортежа в `tui.json`. Все ключи опциональны; отсутствие `tui.json` —
штатный режим. Нераспознанный ключ игнорируется молча; распознанный не того типа —
один warning-тост при старте и значение по умолчанию.

| Ключ | Тип | Дефолт | Смысл |
|---|---|---|---|
| `model` | string `provider/model-id` | — (цепочка) | Recap Model; id может содержать `/` |
| `stale_after` | number | `3` | порог устаревания в пользовательских сообщениях (потребитель — тикет 04) |
| `budget` | number | `12000` | бюджет Recap Digest в символах; переполнение отбрасывается с головы окна |
| `timeout_ms` | number | `60000` | таймаут вызова (потребитель — тикет 04) |

```json
{
  "$schema": "https://opencode.ai/tui.json",
  "plugin": [
    ["/home/<you>/.config/opencode/plugins/recap.tsx", {
      "model": "gonka-proxy/deepseek-ai/deepseek-v4-flash-0731",
      "stale_after": 3,
      "budget": 12000,
      "timeout_ms": 60000
    }]
  ]
}
```

**Регистрируйте файл ровно один раз** (глобально ИЛИ локально): две записи одного
файла дают два инстанса с разными опциями, и клик может достаться инстансу без опций.

## Установка

Симлинк файла в директорию плагинов и запись в `tui.json` — **нужны оба шага**: сканер
TUI-плагинов читает список из `tui.json` (`plugin`), а не сканирует директорию (проверено
на 1.18.21, см. `.scratch/039-tui-session-recap/probe/RESULTS.md`).

```bash
ln -sf "$PWD/recap.tsx" ~/.config/opencode/plugins/recap.tsx
```

Глобальный `~/.config/opencode/tui.json` (или локальный `<project>/.opencode/tui.json`):

```json
{
  "$schema": "https://opencode.ai/tui.json",
  "plugin": ["/home/<you>/.config/opencode/plugins/recap.tsx"]
}
```

Опции передаются кортежем: `"plugin": [["<path>", { ... }]]` — см. раздел «Опции».

## Проверка

```bash
node --test        # юнит-тесты чистой логики (без TUI)
opencode   # открыть TUI в любом проекте
# ctrl+p → «plugins» → supercode.recap должен быть в списке со статусом active
# начать сессию, написать пару сообщений, кликнуть «Recap» в сайдбаре
```

Ожидаемо: кнопка меняется на `Generating…`, затем под ней появляется Markdown ровно с
тремя разделами — `Working on:` / `Done:` / `Next:` — в этом порядке; в списке сессий
одноразовая Recap Session не остаётся (удаляется автоматически).

Чек-лист Digest (тикеты 03):

- сессия, состоящая почти целиком из tool-вызовов, даёт содержательный Recap, а не
  «*No Recap material yet.*»;
- второй клик после успешного Recap сворачивает только сообщения **после** первого
  Recap, а первый подаётся как блок `PREVIOUS RECAP` — хвост не переусаживается;
- ошибка вызова (битая модель, выключенный провайдер) или пустой ответ не сдвигают
  якорь и не становятся `PREVIOUS RECAP`: следующий успешный Recap снова покрывает те
  же сообщения.

Чек-лист цепочки модели (прогнан E2E, см. `.scratch/039-tui-session-recap/probe/RESULTS.md`):

- `model` в `tui.json` → Recap считается указанной моделью (модель видна в SSE-событиях
  assistant-сообщения Recap Session);
- битое значение → **один** error-тост, цитирующий значение и источник, и падение на
  `small_model`; повторный клик нового тоста не даёт;
- оба уровня убраны / битые → работает модель самой сессии;
- опции не того типа (`"stale_after": "many"`) → один warning-тост при старте и дефолты.
